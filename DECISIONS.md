# Decision log

Non-obvious choices in fantasy-bff, one line each. The format and rules are in the monorepo
root's `DECISIONS.md`; choices that span repos go there.

---

[2026-09-11] fantasy-bff: whether the AI projection is served is one answer, `AiProjectionAvailability` (`ai-projection.enabled` AND `security.projection-model-enabled`), enforced at both doors and reported on a new public `GET /api/v1/features` that the web follows — rejected: a field on `/api/v1/versions`, which probes three downstreams per call (10 s read timeouts), so a preset would wait on ESPN's actuator; and folding the two properties into one, which would lose "model off, Who's hot on".
[2026-09-11] fantasy-bff: a shared projection is kept out of search results — `noindex` and no canonical on the crawler preview document, `X-Robots-Tag: noindex` on its card — rather than left indexable as a growth channel; Alexander decided a share is for whoever its author sends the link to, since the share dialog never says the page could appear in search and the title carries the author's username. Taking Googlebot out of nginx's link-crawler map instead was passed over: it would then rely on Google rendering the SPA to read the web's noindex, and bots that do not render would index the bare shell.
[2026-09-11] fantasy-bff: a Paddle checkout attaches the buyer's Paddle customer, found or created by email, and only when the account's email is verified — having the web pass the email to Paddle.js instead was rejected because Paddle does not document combining that with a transaction made on the server, and an unverified address could name someone else's customer and open their billing portal to this account; a lookup that fails opens the checkout without a customer rather than failing the purchase.
[2026-09-11] fantasy-bff: Who's hot's season lengths and default season come from projection-service's `/splits/seasons` (served as `/projection-model/splits/seasons`), and a split with no season is passed on without one, replacing the 82-game constant and "the projected season minus one" (#223, fantasy-projection-service#165) — 2026-27 is 84 games and "minus one" is wrong from opening night on; a free account's explicit window is judged against its own season's length with a service call, taken only for a window of five or fewer, and a constant 84 was rejected because 2025-26's free five (78-82) would then be refused.
[2026-09-11] fantasy-bff: a checkout for an account that already has one it can still pay hands that same checkout back (its Paddle transaction id stored in db-service by compare-and-set) instead of opening another, so two tabs share one transaction that Paddle lets be paid once — refunding a second payment automatically was rejected because the buyer is still charged and the refund waits on Paddle, and keying reuse on the Paddle customer was rejected because accounts with an unverified email have none.
[2026-09-11] fantasy-bff: the four internal API keys, `JWT_SECRET` and `RESEND_API_KEY` have no default and stop startup when blank (#226, #229); a 401 from the startup key check moves readiness to REFUSING_TRAFFIC, which `/actuator/health` (what the container health check curls) now includes, and the Paddle, mock-payment, Google and Facebook secrets keep empty defaults because their features fail closed. Reset/verification links are logged only under `email.log-links`, which only the dev profile sets — "log that sending is disabled" alone was rejected because a deployed instance would then silently send no email, and a 401 on projection-service refusing traffic for the whole bff was accepted since a mismatched key almost always arrives with a deploy, which then rolls back.
[2026-09-15] fantasy-bff: players' pictures sit behind `players.avatars.enabled` (`PLAYER_AVATARS_ENABLED`), off by default rather than set to false per environment, and are stripped in the BFF (player lists, the headshot endpoint, share reads) with no web flag — they are ESPN's photographs, which Disney's terms do not licence for a product with a paid tier, so a deployment that forgets the variable must fail closed; rejected: a web-side flag on `/api/v1/features`, which would leave the endpoint serving the photographs to anyone asking, and dropping the headshot code, since a licensed picture source would reuse the framing and cache.
[2026-09-15] fantasy-bff: `POST /admin/player-ids/remap` takes `to` (default ESPN) and builds the crosswalk from the side being left, gating an apply on that side's players who played, so the pool can move back to Yahoo; a projection or import whose `playerIdSpace` differs from the live pool is served without squaring, and every update carries the pool's space for db-service to refuse a mismatch — a flag flip alone added the whole Yahoo pool beside the ESPN rows on first open and the next save dropped the hidden ones for good; running the reverse only as a one-off script was rejected because the gate, the dry run and the collision rules would have to be copied, and gating on Yahoo's games was rejected because Yahoo's 2026 season lines are empty before the season starts.
[2026-09-15] fantasy-bff: a lone middle initial is dropped from a player's name key, so ESPN's "Elias N. Pettersson" keys as "Elias Pettersson" and the sweater separates him from the centre — the staging remap to Yahoo left his rows in 186 projections behind on his ESPN id; a manual `nhlId:platformId` override was rejected because it is per environment and per direction and the next initial would need another, and dropping every one-letter token was rejected because "J.T. Miller" would become "Miller".
[2026-09-15] fantasy-bff: the `admin` claim needs a verified email as well as an address in `ADMIN_EMAILS` — registration signs an unverified account straight in, so an allowlisted address with no account yet made whoever registered it first an admin, and the repos going public published both the rule and Alexander's addresses (as commit authors); keying admins on user id was passed over as a config change in both environments for the same guarantee, and refusing to sign unverified accounts in at all as reversing the soft gate the product chose. Accounts that existed before email verification were marked verified by db-service V8, so no current admin loses the role.
[2026-09-15] fantasy-bff: WireMock in tests runs with plain HTTP/2 off (`WireMockConfigs.http11()`), and the client tests use the JDK request factory production uses instead of `SimpleClientHttpRequestFactory` — the JDK `HttpClient` asks for h2c over `http://`, and on that path WireMock recorded every POST with an empty body and about one call in 250 reached its journal after the client already had its response, which failed `ResendPasswordResetEmailSenderTest` on CI (0 in 3,400 runs over HTTP/1.1); retrying or awaiting the verify was rejected because the bodies would still be empty, and pinning production clients to HTTP/1.1 because it changes production to suit a test double.
[2026-09-16] fantasy-bff: a projection started from the AI projection records `playerBasis=model`, and a player who joins the pool later gets the model's current line, or last season's where the model has none (every player without an NHL season) — before this the basis was left null and the reconciliation before the write stored `last_season`, so newcomers never saw the model; Alexander chose that a lapsed subscription keeps model lines for newcomers, so premium is not asked on reconcile, but a client-sent `model` basis is kept only with premium or a stored `model` basis, since otherwise any account could claim it and have every omitted row filled from the model. Existing AI projections stay `last_season` (they cannot be told apart reliably); reporting per newcomer whether the model or last season seeded it was passed over, since the notice would need a second persisted list for one sentence.
[2026-09-16] fantasy-bff: `GET /api/v1/espn/credentials/values` is removed with espn-service's endpoint behind it, so no BFF route returns a user's stored ESPN cookies (espn-service#31, web#676) — the only caller prefilled masked fields, and a readable session cookie turns any XSS or stolen SlapStat session into a stolen ESPN login.
[2026-09-16] fantasy-bff: `GET /api/v1/versions` stays public, with a 10-second shared cache in `VersionService` and a per-IP limit of 30 a minute, rather than closed behind a token — the promotion workflows poll production's copy unauthenticated and hold no token the BFF could check without a new secret in four repos, and the versions it reveals are already public as each repo's published GitHub releases, so closing it would cost a secret and hide nothing; the cost that was real is the four-service fan-out per request, which the cache ends.
[2026-09-16] fantasy-bff: verification and password-reset emails are capped per address (3 an hour each, `emails-per-address`) on top of the per-IP rules for `/verify/resend`, `/verify` and `/refresh` — a per-IP limit stops one caller but not many callers aiming at one inbox; the cap answers 200 and sends nothing, so it reveals no more about an account than the endpoints already do, and the password-reset path got it too because it sends mail to a caller-chosen address the same way.
[2026-09-16] fantasy-bff: "sign out everywhere" is `POST /api/v1/account/sessions/revoke`, which bumps the account's `tokenVersion` in db-service, and `/refresh` keeps issuing a new refresh token without invalidating the old one — true rotation (the old token refused once used, reuse detected) needs a record per issued token, and doing it with the one counter would sign out every other device and every other tab racing the same refresh on each refresh; a per-session token table was passed over as the first server-side session state in a stateless BFF, for a gain (revoking one device, catching a replayed token) the finding did not need. Access tokens stay valid for their 15 minutes after a revoke.
